# 0.14.4 质量、性能与限制

本页区分已测结果和目标。程序从视频画面读取已有对白，不通过音频、翻译或语言模型补写内容。导出条数减少只能作为碎片化的代理指标，不能代表文字准确率。

## 已测结果

- 本地 212 项回归通过；覆盖连续 OCR 波动、真实短词变化、空白、标点、数字与否定词边界。固定离线图片检查了简中/英语、韩语、日语、繁中、拉丁语系和泰语模型路线。固定图片不等于真实剧集逐字验收。
- Mac 上一段 148.821 秒、544×960、28 fps 的真实泰语样片，同一人工框选区域、冷缓存完整处理：旧版 RapidOCR 路线约 **399.76 秒 / 4012 MB**；0.14.4 在 macOS 15 使用系统 Vision 为 **109.82 秒 / 1093 MB**。字幕 163→88 条、短于 0.18 秒的条目 138→25 条。两版识别后端不同，不能把条数当成字符准确率；25 条碎片依然需要继续处理。
- 同一真实韩语样片用原区域、原语言和 Apple Vision 冷缓存回归，23 条的文字与起止时间全部和上一版一致。在 Mac 上强制使用 Windows 所用的 RapidOCR 韩语模型，修复两处词间空格波动后由 25 条变为 23 条、零极短条；这只是跨平台代码与模型路线的代理验证，不是 Windows 真机长跑。英语 111.678 秒样片保持 61 条、无短于 0.18 秒的条目；中文 83 秒样片与旧版 40 条的文字和时间轴逐条相同。
- macOS 15 已确认 Vision 的泰语语言支持；macOS 14 和 Windows 的自动泰语路线仍为随包 RapidOCR。三档速度模式只调整资源，不改变 OCR 对象与分段规则。

## 仍待验证

- 还没有中、英、韩、泰及其他语言多部剧的逐帧人工真值。特别是泰语样片仍有极短重复和个别缺字，不能宣称完全解决或给出可信的字符准确率。
- Windows 不同 CPU、内存、显卡与系统版本的冷缓存整剧处理尚未做多机型验收；Mac Vision 的性能不能外推为 Windows 速度。
- 用户提出的 **100 分钟视频在 5–10 分钟完成**尚未达到。当前仍对大部分视频帧调用 OCR，长视频耗时可能很高；不能通过丢弃短字幕换取速度。
- 已绕开一条 Mac 下拉弹层崩溃路径，长期稳定性仍需观察。安装包尚无公司代码签名，Mac 尚无 Apple 公证。
